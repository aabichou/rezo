ZLT X31 web API, mapped for a monitoring dashboard

I reverse-engineered the Ooredoo-branded ZLT X31C (5G NSA CPE, Quectel RG520N modem) from its Vue web UI and probed it live on 21 Oct 2026. Below: how auth works, which commands are safe to poll, what each returns, and the traps.

Host 192.168.100.1 Firmware 1.0.0.24 (shown as 1.0.0.16) Config X31-TN0303_1.0.10 Commands defined in UI 353 Probed live ~60

Transport

There is a single endpoint. Every request is a JSON POST to /cgi-bin/http.cgi over HTTPS with a self-signed certificate. The operation is a numeric cmd. Reads put "method":"GET" in the body. Writes use "method":"POST" and also send the login token.

POST https://192.168.100.1/cgi-bin/http.cgi
Content-Type: application/json

{"cmd": 1002, "method": "GET", "sessionId": "<64 hex>"}

Every value comes back as a string, numbers included, and fields with no data are "". Errors look like {"success":false,"message":"…"}. You will see these messages:

messagemeaning
NO_AUTHThe session is missing, or another login replaced it. Log in again.
LOGIN_TIMEOUTThe session expired from idleness. Log in again.
LIMITED_ACCESSThe command is reserved for a higher account level than admin (level 3). This covers SMS, band lock, PLMN lock and cell lock.
Parameters of the CMD can't identifyThe command doesn't exist on this build, or it needs a subcmd.
NOT SUPPORTThe feature is compiled out (mesh topology, for example).
empty body / connection resetThe feature is absent on this model. Treat it as unsupported.

Authentication

Get a token

{"cmd":232,"method":"GET"} returns token. No auth is needed.

Hash

passwd = sha256(token + password), as lowercase hex.

Log in

cmd 100, POST, with username, passwd, token and isAutoUpgrade:"0".

Use the session

The response carries a sessionId. Send it on every call.

Only one session can exist. I verified this live: a new login immediately invalidates the previous sessionId. A poller that logs in will log you out of the browser UI, and opening the UI will break the poller. Build the poller to re-login on NO_AUTH, and avoid authenticated polling while someone is using the UI.

Idle timeout: The session stayed valid after 5 minutes with no requests; I stopped measuring there. Either way, re-login on LOGIN_TIMEOUT/NO_AUTH and the client handles it.

Failed logins are rate-limited. After 3 bad passwords the box locks you out for a cooldown, and cmd 232 reports it in netx_login_time.

No-auth endpoints

These answer with sessionId:"", so a poller can read signal and status without taking the session, which sidesteps the single-session problem for the most important metrics.

Gotchas

  • There is no live throughput field. lte_dl_speed, netWanRxRate and lanRxRate exist but are always empty. Diff two readings yourself.
  • WAN byte counters are coarse. wan_rx_bytes/wan_tx_bytes move in 1 MiB steps. flow_dl/flow_ul (MB, 2 decimals, so 10 kB resolution) are better for rate math. Poll every 5–10 s and divide the delta by elapsed time.
  • Session and monthly counters reset. flow_* resets on reconnect and mon_* on the billing day. Handle negative deltas as resets.
  • Carrier aggregation is packed into strings. currentband "20+3+1", bandwidth "10+20+20", FREQ "6400+1800+101" and PCI "419+419+419" are parallel +-separated lists, primary cell first.
  • Memory math. The UI computes used = total − free − cache from the first three values of memory.
  • Fake version. The UI shows fake_version 1.0.0.16. The real build is real_fwversion 1.0.0.24.
  • Sensitive fields. cmd 2/211 (Wi-Fi config) return the Wi-Fi key in clear text, and the 2.4G SSID is base64-encoded. Don't log those responses.

Commands a poller must never send

Some commands act even when called with method:"GET". A dashboard has no reason to touch these:

cmdwhy
6 · 99 · 112 · 159Reboot or factory reset
116 · 228 · 288 · 342 · 464 · 489Network, cell or Wi-Fi scans. These drop or degrade the link while running.
45 · 46 · 51 · 186 · 187 · 270Raw AT and shell commands
5 · 105 · 106 · 196 · 198 · 239Firmware upgrade paths
249 · 250 · 517 · 539 · 350eSIM reset/download, web data clear, self-check, USSD
101Logout. Harmless, but it ends the shared session.

Suggested dashboard architecture

Fast loop, no auth

Every 5 s: 133 + 113. Signal, cell, bands, link state and battery, all without taking the session.

Slow loop, auth

Every 30–60 s: 1002, 1001, 1000. Throughput deltas, CPU, temperature, memory, clients and quota. Re-login on NO_AUTH.

Store

Write normalized numbers to a time-series DB (Prometheus exporter, InfluxDB or SQLite). On startup, backfill from 1015/1016/1014.

Render

Grafana or a small web app. Key panels: SINR/RSRP per leg, band and cell changes as annotations, DL/UL rate, monthly quota, temperature, clients by RSSI.

To be polite to the UI, pause the authenticated loop whenever the poller gets NO_AUTH right after a successful call. That means someone else just logged in. Back off for a few minutes instead of fighting over the session.
